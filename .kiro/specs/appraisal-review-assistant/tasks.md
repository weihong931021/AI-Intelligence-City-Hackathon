# Implementation Plan: Appraisal Review Assistant

## Overview

以 Python 3.12 建立審查引擎，外掛規則庫、說明層與介面。任務排序以「先讓審查結果正確，再讓它好看」為原則：L1–L7 檢查層完成即具備可展示的核心價值，說明層與介面依剩餘時間加上。標記 `*` 的測試子任務為可選，但任務 2 的公式回歸與任務 8 的黃金案例測試**不可略過**，因為它們是審查結果可信度的唯一保證。

決賽時程為 9/12–9/13，交件截止 9/13 13:00。Wave 1–5 為必須完成的最小可展示範圍。

## Tasks

- [ ] 1. 建立資料模型與案件載入
  - 建立 `src/appraisal_review/` 套件與三表的結構化型別。
  - _Dependencies: none_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_
  - [ ] 1.1 定義 Case_Bundle、三表欄位與 Finding 模型
    - 在 `models.py` 定義 Survey_Form、Regional_Factor_Form、Comparison_Form 與 Finding。
    - 欄位值以三態表示：有值、`EXEMPT`（免修正 `−`）、`MISSING`（缺漏），禁止以 `0` 代表後兩者。
    - _Requirements: 1.4, 1.5, 4.6_
  - [ ] 1.2 實作案件載入與範圍判定
    - 在 `case_loader.py` 由 JSON 載入 Case_Bundle，記錄案號、年期、區段編號、用地類型與比準地地號。
    - 缺表時輸出可執行的審查範圍與受限檢查項目清單。
    - _Requirements: 1.1, 1.2, 1.3_
  - [ ] 1.3 建立官方範例案件的 JSON 樣本
    - 依 `官方資料/範例/查估書表範本.pdf` 建立區段 P002-00、案號 1140901-99-001 的完整三表 JSON。
    - 此樣本為後續所有測試的黃金案例，數值須逐格核對書表範本。
    - _Requirements: 1.1, 1.2_
  - [ ]* 1.4 撰寫模型與載入單元測試
    - 驗證三態欄位序列化往返、缺表時的範圍判定。
    - _Requirements: 1.3, 1.4, 1.5_

- [ ] 2. 建立評價基準規則庫與矩陣產生器
  - 將商業用地基準表轉為 Criteria_Table，並以公式生成修正率矩陣。
  - _Dependencies: 1_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7_
  - [ ] 2.1 定義 Criteria_Item schema 與級距判定型別
    - 在 `criteria.py` 定義 `range`、`in_district`、`category`、`boolean` 四種級距規則。
    - 記錄來源文件與頁碼供 Rule_Citation 使用。
    - _Requirements: 2.1, 2.2, 2.7_
  - [ ] 2.2 實作 Matrix_Formula 產生器與 override 機制
    - 依「(比較標的等級序 − 比準地等級序) × Max_Adjustment ÷ (等級數 − 1)」生成矩陣。
    - 支援逐格 override，override 優先於公式結果。
    - _Requirements: 2.3, 2.4, 2.5_
  - [ ] 2.3 建置商業用地 Criteria_Table
    - 由 `官方資料/範例/評價基準明細表範例.pdf` 抄錄各細項的 Max_Adjustment 與 5 段級距定義。
    - 僅抄錄上限值與級距，矩陣數值不手動輸入。
    - _Requirements: 2.1, 2.2, 2.7_
  - [ ] 2.4 執行公式對官方基準表的逐格回歸比對
    - 比對公式生成結果與官方基準表所有儲存格，輸出差異清單。
    - 差異儲存格一律寫入 `overrides` 並記錄原因，不得調整公式去遷就個案。
    - _Requirements: 2.5, 2.6_
  - [ ]* 2.5 撰寫規則庫單元測試
    - 覆蓋兩級距細項、五級距細項、override 優先序與級距端點判定。
    - _Requirements: 2.3, 2.4, 2.5_

## Notes

- 任務 `1` 到 `12` 的相依關係以 Task Dependency Graph 為準；同一頂層任務的子任務依編號順序執行。
- 標記 `*` 的測試子任務為可選；任務 2.4（公式回歸）與 8.3（黃金案例驗收）不在此列，兩者為必要。
- Wave 1–5（任務 1–8）完成即具備可展示的核心審查能力；時間不足時優先保住這段，介面可簡化但審查結果不可失準。
- 任務 12 為第一版之後的範圍，列於此處以確保架構預留擴充點。
- 本計畫不包含自動蒐集土地條件與成交案例、自動選取比較標的，或商業用地以外的規則庫建置。
