# AI 輔助不動產估價案件審查

2026 新北市 AI 智慧城市黑客松競賽｜**地政局組**參賽專案。

決賽：2026/09/12–09/13，新北市政府 603 大禮堂。

## 題目

不動產估價案件在審查時，需依估價師填寫的估價書表，逐一檢核其是否依「評價因素基準明細表」正確判定優劣等級及修正率。審查人員必須人工比對多張表單（地價區段勘查表、影響地價區域因素分析明細表、比較法調查估價表），逐項核算距離、級距、修正率與加總結果。

命題文件指出的痛點：

1. 估價書表涉及表單眾多，人工逐項比對耗時且易發生疏漏。
2. 區域因素與個別因素需依不同用地類別基準明細表判定，人工判讀一致性不易維持。
3. 修正率加總及跨表抄填（如區域因素總修正數）容易出現計算或填載錯誤。

## 決賽題目（9/12）

決賽指定**樹林區普通住宅用地**的比準地 P001-00 與三個比較標的 P002／P003／P004，價格日期 2022-09-01。給的是 4 個區段的表3 已填值、待完成的表5 與表4、9 頁評價基準、3 份 Excel 範本。主辦方說得很直接：手填是長官平常在做的事，不是加值 —— **100 分是空白表丟進去系統填完，退一步是逐格告訴長官該填什麼**。

主辦方口頭澄清兩件表上看不出來的事：捷運開發區用都市計畫變更前的分區（四筆都是第一種住宅區）；宗地臨路 8 米以下巷道容積率一律降為 200%（表上的 260% 不能直接用）。細節見 [決賽說明會-主辦方補充說明](決賽說明會-主辦方補充說明.md)。

## 解法

輸入 4 個區段，系統補查空白設施欄位、依兩層基準判級、算修正率、串到價格，產出可照抄或匯出的表3／表5／表4，每一格點開有距離證據、法規依據、矩陣查值。填完再用同一套引擎重跑一次當自我驗證。

設計上最重要的兩條界線：**數值由程式決定，文字由模型生成**；**表上的值不一定是評比值**，記載值與評比值並列。

```text
資料蒐集    區段範圍 → 設施距離 → 證據（值、來源、量測基準、時點）
              │
案件層      題目已填值 ＋ 法規覆寫（捷開區分區、容積率 200%）
              │
規則庫      區域因素（p.1–5，對象區段）＋ 個別因素（p.6–9，對象宗地）
              │
計算引擎    判級 → 矩陣 → 小計／總修正 → 表4 串接 → 三價收斂；純函式、可單元測試
              │
說明層      Amazon Bedrock：轉白話並引用出處，不產生任何數字
              │
輸出        逐格建議＋證據、缺漏清單、匯出官方 Excel 三個工作表
```

### 兩層基準一起用

區域因素比的是**區段對區段**，個別因素比的是**宗地對宗地**，同名細項（接近學校、地勢、停車）在兩層各判一次不算重複。例外只有使用分區、建蔽率、容積率 —— 兩層是同一個數字，題目明定只在表4 算。

修正率矩陣為等差反對稱，只抄每個細項的上限值與級距，矩陣由公式生成（容積率 25 ÷ 4 = 6.25、其他影響因素 20 ÷ 6 = 3.33）；建置時逐格回歸，差異寫成 override。

### 本案不用做的、要做的

不用做：找哪個特徵影響價格（權重寫死在矩陣裡）、選比較案例（已指定）、算價格日期調整（已給）。

要做：補 4 個區段的空白設施欄位並附出處；判「其他影響因素」（唯一七級項目，靠舉證）；容積率依土地開發分析法與區域因素接續而非重複；三個試算價格收斂成一個比準地地價。土地使用管制四項在本案全為 0%，價差來自交通、公共建設、特殊設施、污染、其他影響因素。

## 開發

需求：Python 3.12+，無外部相依套件（測試使用標準函式庫 `unittest`）。

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -t .
```

目前 65 個測試全數通過，涵蓋既有的資料匯入模組。填表引擎的測試將隨 [任務計畫](.kiro/specs/appraisal-review-assistant/tasks.md) 逐步加入。

### 開發限制

- 基礎模型**僅限使用 AWS 服務提供者**（依錄取信及競賽附則）。
- 提交前確認未包含 AWS Access Keys、API Tokens、資料庫密碼等憑證；憑證一律以環境變數管理。
